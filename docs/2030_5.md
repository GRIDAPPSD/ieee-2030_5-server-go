# IEEE 2030.5 (SEP2) reference

This server implements the IEEE 2030.5-2018 Smart Energy Profile (SEP2). It
ships a protocol listener for device traffic and an admin listener for the
operator surface; this document covers the protocol side. For the admin
surface see [`admin.md`](admin.md). For the CSIP V1.2 profile layered on
top, see [`csip.md`](csip.md).

The protocol router and route registrations live in
[`BuildProtocolRouter`](../pkg/sep2srv/assembly/assembly.go);
[`internal/server/router.go`](../internal/server/router.go) now holds only
the shared `Stores` type. Handlers live in
[`pkg/sep2srv/handlers/<name>/`](../pkg/sep2srv/handlers/), one
subpackage per function set. Public Go types for every resource live in
the `pkg/sep2` package of the GRIDAPPSD/ieee-2030_5-core-go module.

## Function-set support

Status vocabulary:

- **Supported** - wire-conformant: routes registered, handler returns the
  spec resource, persistence wired through `pkg/store`.
- **Partial** - at least one route is wired but a non-trivial slice of the
  function set is missing (deferred sub-resources, mode coverage gap,
  no admin visibility, etc.). The "Notes" column names what is missing.
- **Planned** - not implemented; tracked. Cross-references the open ticket
  if one exists.
- **Not Started** - required by spec but no code yet.

## Transport

The protocol listener binds `SEP2_ADDR` (default `:443`) and requires
mutual TLS. Every request walks
[`auth.IdentityMiddleware`](../internal/auth/identity.go) (extracts
SFDI/LFDI from the peer cert) and
[`auth.ACLMiddleware`](../internal/auth/acl.go) (per-prefix method/auth
bitmap, longest-prefix match).

The default ACL - `auth.DefaultACLRules()` in `acl.go` - covers `/dcap`,
`/tm`, `/sdev`, `/edev`, `/mup`, `/dc`, `/upt`, `/rt`, `/msg`, `/rsps`.
`/dcap` and `/tm` allow `AuthNone | AuthDeviceCert`; everything else
requires `AuthDeviceCert`.

The server offers **[CCM-8](glossary.md)** only (`make run`, `make run-ccm`,
`make run-full`) - the `pkg/sep2tls/gotls` fork in the
GRIDAPPSD/ieee-2030_5-core-go module registers
`TLS_ECDHE_ECDSA_WITH_AES_128_CCM_8` (code point `0xc0ae`). There is no
[GCM](glossary.md) fallback; a client that cannot offer CCM-8 is refused at
the handshake. See [`csip.md`](csip.md) for the spec context.

## Wire encoding

XML only (`application/xml`). `encoding.NamespaceMiddleware`, in the
`pkg/sep2/encoding` package of the GRIDAPPSD/ieee-2030_5-core-go module,
wraps the entire router and rewrites the namespace declaration on the way
out for legacy 2013 clients (the EPRI reference client lives in this
group).

## Discovery

mDNS advertisement is opt-in via `SEP2_MDNS=true`
([`internal/discovery/`](../internal/discovery/)). Service type
`_smartenergy._tcp` advertises the bound `SEP2_ADDR` under the
`SEP2_MDNS_HOST` name.

## Device certificates

**The default device-certificate hardware type is `1.3.6.1.4.1.40732.99`, a test value under the IEEE 2030.5 arc; production devices use their manufacturer's PEN.** `SEP2_HW_TYPE` changes it for the server API and `sep2server certs`; it takes a full OID (valid `1.3.6.1.4.1.40732.99`, invalid `40732`), unlike `SEP2_PEN`, which takes only the bare number (valid `40732`, invalid `1.3.6.1.4.1.40732`). A malformed value stops startup. **The default `SEP2_PEN`, which embeds the server's PEN in minted mRIDs, is `40732`, the IEEE 2030.5 test PEN; production servers set their own manufacturer PEN** (`SEP2_PEN=40732` is valid, `SEP2_PEN=1.3.6.1.4.1.40732` is invalid; `SEP2_HW_TYPE=1.3.6.1.4.1.40732.99` is valid, `SEP2_HW_TYPE=40732` is invalid). `make certs` and `make new-device` (and `scripts/new-device.sh`) also read `SEP2_HW_TYPE`, and `HW_TYPE` overrides it for them. See the README section "Device certificate hardware type".

## Persistence

`SEP2_DATA_DIR` is the single knob (#165). Empty keeps the
historical pure in-memory behavior; non-empty turns on disk-backed
EndDevice, Registration, DERProgram, Subscription, and AdminFSA
(#163) stores. The deprecated `SEP2_SUBSCRIPTION_STORE_PATH` is
preserved as an override when both are set.

### Flow reservation hold

`SEP2_FLOW_RESERVATION_DEADLINE_SECONDS` (whole seconds, 1 to 3600, default
300; #763) is how long a FlowReservationRequest waits for an operator answer
before the server's fallback decides. Any other value stops startup. With
`SEP2_DATA_DIR` set, a request still waiting at a restart gets the rest of its
hold from its own creationTime, and one already past it is decided at start.

`SEP2_FLOW_RESERVATION_RETENTION_GRACE_SECONDS` (whole seconds, 900 to 604800,
default 1800; #672) is how long a request and its responses stay readable after
every response has ended. The server then removes them, at startup and every
minute after. The floor is the 900 s poll rate the response list advertises.
A request that has no response is never removed. Any other value stops startup.

### Device comms threshold

`SEP2_COMMS_OFFLINE_AFTER_SECONDS` (whole seconds, 1 to 86400, default 300;
#875) is how long a device may go without a request before the admin Devices
payload reports `comms` as `offline`. A device is `online` while its last
request is younger than the threshold, `not_seen` if it has made none since
the server started, and `unknown` when nothing records requests. Only
requests that pass identity and the ACL count. The record is in memory, so a
restart clears it. Any other value stops startup.

### Mirror reading retention

Readings posted to `POST /mup/{id}/mr` are kept in memory only, with or
without `SEP2_DATA_DIR`, so a restart loses all of them. A DER control's
delivery figure then reads its window as uncovered until new readings arrive;
the gap is never filled.

`SEP2_MIRROR_READING_RETENTION_SECONDS` (whole seconds, 87300 to 2592000,
default 90000; #806) is how long a reading is kept after the server received
it. The server removes older readings at startup and every minute after. The
floor is the longest DER control the server issues (24 h) plus the furthest one
reading can reach in the delivery figure (900 s), so a live control never loses
a reading its figure uses. Once a control's window needs a reading older than
the retention, which happens to every ended control in time, its delivery
carries `readingsExpired: true` and a null figure, so it never reads like a
device that did not report.

`SEP2_MIRROR_READING_MAX_PER_SERIES` (whole number, 292 to 2592000, default
20000) caps the readings kept per series: beyond it the oldest of that series
are removed and a warning names the mirror and the series. A series is one
mirror's real power readings on one leg of the delivery figure (qualifier,
Average or instantaneous, and phase: total, A, B or C) with one
flowDirection, whatever their mRIDs, so a client that sends every reading
under a fresh mRID is still capped. All of a mirror's other readings (VAr,
volts, frequency and the rest) share one series. The floor holds one reading
every 300 s across the retention floor, so a leg posted at that rate never
loses what the retention keeps; the default does the same for one reading
every 4.5 s over the default retention. The shared series is held to the same
cap, so a mirror posting many non-power quantities fast loses its oldest of
those first; the delivery figure does not read them.

When a series' only ReadingType is on a reading due for removal while a newer
reading of the same mRID remains, out of band or inline in its
MirrorUsagePoint, that typed reading is kept. Readings sent inline in a
MirrorUsagePoint are never removed. Any other value of either setting stops
startup.

### Traffic capture

`SEP2_TRAFFIC_CAPTURE=true` (#628) is required before request/response
recording for the protocol listener turns on, in either cipher mode; off
by default, and off means off regardless of `SEP2_DATA_DIR`. Permitted,
`SEP2_TRAFFIC_DIR` names the segment directory, else it falls back to
`<SEP2_DATA_DIR>/traffic`; if neither resolves, or the resolved directory
is refused (a foreign file or a symlink), capture stays off. Every one of
these outcomes logs exactly one boot line naming which it is, and an
enabled boot names the directory too. The recorded exchanges are
segmented, size-capped (600 MB), wiped on every startup, and readable at
`/api/traffic/*` on the admin listener, behind the same auth as every
other admin route; a non-GET method on those routes answers 405, not 404.

### Device log files

The server keeps one log file per device certificate (#1063): JSON lines in
`<LFDI>.jsonl`, rotated to `<LFDI>.1.jsonl` before a file would pass the
limit, with one rotated file kept, so a device holds at most twice the limit.
The writer never blocks a request; a full queue drops the line and counts it.
No request writes to it yet; the sources arrive in later changes.

| Variable | Meaning |
|---|---|
| `SEP2_DEVICE_LOG` | `false` turns it off; unset or `true` is on. Any other value stops startup. |
| `SEP2_DEVICE_LOG_MAX_BYTES` | Whole bytes per file, 1000000 to 20000000, default 20000000. Anything else stops startup. |
| `SEP2_DEVICE_LOG_DIR` | Directory, default `./etc/sep2/logs` under the working directory. `SEP2_DATA_DIR` does not move it; set `SEP2_DEVICE_LOG_DIR=$SEP2_DATA_DIR/logs` to put it there. |

A directory you set that cannot be created, is not a directory, is not
writable, or is the certificate directory (or the directory holding the
server key, the CA keys or the admin key) or inside it stops startup with an
error naming `SEP2_DEVICE_LOG_DIR`. So does a directory writable by every
user; a group-writable one starts with a warning. The writer never opens a
log file through a symlink. The default directory that cannot be used only turns
the log off, with the boot line `device log disabled: ./etc/sep2/logs: ...`.
The worst case is two files per device at the limit; there is no cap across
devices. The repository ships the default folder with a `.gitkeep` and
ignores everything else in it.

The admin listener reads the log (#1066) at `GET /api/device-logs/{lfdi}`,
newest line first, and `GET /api/device-logs/{lfdi}/download`, which is the
device's own two files oldest first as `application/x-ndjson`. Both need a real
credential, loopback included, and answer 503 `device log disabled` when the log
is off. Query parameters of the first: `limit` (1 to 1000, default 200; anything
else is 400), `before` or `after` (a cursor taken from an earlier page, not
both), `kind` (a comma list such as `request,logevent`) and `scope` (`own`, the
default, or `managed`). A page reads across the rotated file and merges the
device's own file, its lines in the shared `unregistered.jsonl` (lines written
before its registration was known), and its manager's lines that name it, each
marked in `source`. `scope=managed` on an aggregator adds each managed device's
file. Lines are ordered by their time `t`, not by `seq`, because `seq` is per
file; the cursor is opaque and stays valid across a rotation. The body is
`{"lfdi", "entries", "nextBefore", "nextAfter", "rotatedRead", "dropped"}`:
`entries` is `[]` when nothing matches, `nextBefore` is null on the last older
page, `nextAfter` is the cursor to poll with for newer lines, and `dropped` counts
lines the writer lost since start. An `after` page returns the oldest `limit`
lines newer than the cursor, so following `nextAfter` skips none. 404 means no
file and no line in the shared or manager files exists for the device. A page stops reading a file once it is more than 10
seconds older than the oldest line it needs, which is how far a line can trail
the lines written before it.

A `request` line for an answer with status 200 to 299 carries `location` when the
response set a `Location` header that starts with `/` (a create's new href),
capped at 256 bytes; a GET carries none.

A successful protocol GET of a DERControl list, one DERControl or a
DefaultDERControl carries `mrids`, the mRIDs it served (32 uppercase hex digits,
at most 8), and `mridsMore`, how many served controls are not named there
(absent when 0; a malformed mRID is counted, never written). Admin reads of the
same stores carry neither.

A `POST /rsps/{set}/rsp` line with status below 400 carries `subject` (the
event mRID the Response answered, uppercase), `rspStatus` (the Response status
code, when the body had one) and `target` (the `endDeviceLFDI` it names, only
when that is not the caller, such as an aggregator posting for a managed
device; the line then shows in that device's view). A subject that is not 32
hex digits is recorded as `"subjectInvalid": true`, never as text. A refused or
malformed POST carries none of these.

### Boot fixture and the data_dir

`SEP2_BOOT_FIXTURE` loads a YAML fixture at startup. Without
`SEP2_DATA_DIR`, every fixture record is created on each boot.

With `SEP2_DATA_DIR` set, the fixture is a seed that yields to
persisted state (#352). EndDevice, DERProgram, DERControl and
DefaultDERControl, the fixture kinds whose stores persist, are applied at most once per record per
data_dir. The records applied so far are listed in
`<data_dir>/bootfixture-seed.json`. That file is written only after
every store write it covers has succeeded, and a record never leaves
it.

| On a later boot | Result |
|---|---|
| A fixture record was edited through the protocol or the admin plane | The edit is kept. |
| A fixture record was deleted | It stays deleted. Fixture records under a deleted EndDevice or DERProgram are not created either. |
| A record was added to the fixture | It is created. |
| A persisted record is not yet in the seed record | It is adopted unchanged. An EndDevice is adopted only when its LFDI matches the fixture's, ignoring case, and only when no other persisted EndDevice holds the fixture's SFDI or LFDI (see the row below). |
| A seeded EndDevice id is now held by a different LFDI (deleted, then reallocated) | It is treated as deleted: the other device is unchanged and receives no fixture records. |
| An unseeded fixture EndDevice names an id held by a different LFDI, or carries an LFDI or SFDI that another persisted EndDevice holds | Startup fails before anything is written. The error names the fixture entry, the id, which identifier is held, and the holding EndDevice's href. It prints no full LFDI or SFDI, but for an admin- or auto-registered holder the href itself carries the holder's first 8 SFDI digits. |
| The seed record exists but cannot be read, is empty, is undecodable, has an unknown version, lists no records, or holds a key that does not fit its kind | Startup fails before anything is written. |

FunctionSetAssignments and DERCurves are not persisted, so they load
from the fixture on every boot, except under a skipped EndDevice or
DERProgram. DERControls and DefaultDERControls persist and seed once:
an operator edit or delete of a fixture record survives a restart.

Each skipped record is logged once per boot, without any LFDI, and so
is each DERControl or DefaultDERControl skipped with its parent.

```
boot fixture: skipping EndDevice id="<id>": deleted since seeded
boot fixture: skipping EndDevice id="<id>": id now held by another identity
boot fixture: skipping DERProgram edev="<id>" id="<id>": parent EndDevice skipped
boot fixture: skipping DERProgram edev="<id>" id="<id>": deleted since seeded
boot fixture: skipping DefaultDERControl scope="<edev>/<fsa>/<program>": parent DERProgram skipped
boot fixture: skipping DefaultDERControl scope="<edev>/<fsa>/<program>": seeded but absent from the persisted store
```

To re-seed, stop the server and delete `bootfixture-seed.json`. The
next boot adopts the fixture records that are present and recreates
the ones that are absent. A data_dir used before this behavior has no
seed record, so its first boot does the same.
